# 長期記憶の再設計（Stage 1, 第2ラウンド）

第1ラウンドでは、長期記憶を外したほうが OOD-深さ の正答率が高かった（48% 対 40%）。
原因を調べ、作り直し、複数シードで比べた。

## 1. 原因の切り分け

第1ラウンドの OOD-深さ で、「記憶ありだと不正解・記憶なしだと正解」だった21問を調べた。

| 仮説 | 結果 |
|---|---|
| 記憶の候補が、見える例には合うが間違いで、早期停止を招いた | **主因ではない**。見える例に合う誤答は、記憶あり16件・なし15件でほぼ同じ |
| 記憶のマクロが組み合わせ探索の予算を浪費した | **主因**。21問中17問が予算切れ（2,000回）。マクロに固定の重み 0.15 を与えていたため、無関係なマクロの組み合わせが上位に来ていた |

## 2. 新しい設計（v2）

| | v1（初版） | v2 |
|---|---|---|
| 記憶からの候補 | 特徴が似た順に上位8件 | 特徴の類似度が0.8以上の経験だけ。似た経験がなければ何も出さない |
| マクロの重み | 固定値 0.15 | 検証済みの経験で使われた回数（類似度で重みづけ）に比例。2回以上現れたものだけを使う。マクロ全体の確率質量は λ = S/(S+10)（上限0.3） |

## 3. 評価条件

- 3シード × 5分割 × 100問 = 各構成1,500問。同じ問題を同じ順で流す（記憶は分割をまたいで蓄積）。
- **OOD-関連**を追加した。以前に解いた ID の規則に1手順を足した3段階の問題で、経験が役に立ちうる状況を表す。
  記憶に有利になるよう作った分割なので、他の分割とは分けて解釈する。
- 良い記憶の条件は2つ: (1) 経験が無関係なときに邪魔をしない、(2) 経験が関係あるときに役に立つ。

## 5. 判定

- **v1（初版）は効果なし**: 記憶なしと全体で +117 / −118。OOD-深さ では悪化傾向（p=0.12）。
- **v2 の記憶検索は有意に効く**: 記憶なしに対して全体で +137 / −82（p=0.0002）。
  - OOD-関連（経験が役立つ状況）: 44.0% → 52.0%（p=0.008）
  - Few-shot: 73.7% → 78.0%（p=0.04）、OOD-組み合わせ: 82.7% → 85.7%（p=0.05）
  - OOD-深さ（経験が無関係な状況）: 48.0% → 49.0%。**邪魔をしなくなった**（v1 は 43.0%）
  - Simulator 回数は 618 → 501 に減り、実時間も 110ms → 98ms に短縮
- **v2 のマクロは上積みなし**: 検索のみに対して +48 / −58（p=0.38）。OOD-関連 ではむしろ下がる傾向（52.0% → 48.3%）。

→ 原則に従い、提案モデルの既定を **v2 の記憶検索のみ（マクロなし）** に変更した。
マクロの実装は残してあり、`use_macros=True` で使える。

### 仮説 H5 の再判定

「長期記憶は OOD-深さ で効く」→ **棄却のまま**。ただし記憶は、Few-shot・OOD-組み合わせ・OOD-関連 では有意に効く。
効き方は「似た経験の結論をそのまま再利用する」ことであり、「部分手順を組み合わせて深い問題を解く」ことではなかった。

## 6. 限界と次の課題

- マクロ（ライブラリ学習）が効かなかったのは、組み合わせ探索の予算2,000回に対して部品の候補が多すぎるからかもしれない。予算や問題の深さを変えて再検証する余地がある。
- 発見ループ（`core/discovery`）の記憶は、今回は再評価していない（v2 のマクロを使う設定のまま）。
- 他のアブレーション（docs/04_results.md の表）は v1 の記憶で測ったもの。既定の変更後に全体を再測定する必要がある。

再現方法:
```bash
for s in 0 1 2; do python -m evaluation.memory_eval --seed $s & done; wait
python -m evaluation.memory_eval --aggregate
```
