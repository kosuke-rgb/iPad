# 相談用まとめ: 脳に着想を得た小型AI（2026-09-27、フェーズ1終了時点）

このまとめ1つで、プロジェクトの目的・設計・実験結果・未解決の問題が分かるように書いています。
数値はすべて実際に実験して得たものです。「暫定」と書いたものは、まだ全シードがそろっていません。

---

## 1. 目標

- 最終目標: **人間の脳とほぼ同じ働きをするモデルを AI で再現すること**。
- 当面の方針: 小型 LLM を中心に、記憶・専門家・動的な計算・仮説生成・検証・自己改善などの認知モジュールを組み合わせる。
  巨大なモデルに頼らず、少ない経験から未知の問題に適応できるかを検証する。最終的にはスマートフォンで動かす。
- 開発の原則: 「脳に似ている」ことを成功の根拠にしない。各モジュールを ON/OFF して、**実際に性能が上がったか・どれだけの計算で上がったか**を実験で判断する。効果がなければ削除する。

## 2. 実験の舞台（なぜこの課題か）

言語タスクでは「未知の問題への強さ」や「発見」を自動で公平に採点しにくいため、最初の舞台を
**「数個の入出力例から、隠れた規則（整数リストを変換するプログラム）を見つける」** 課題にした（ARC に近い）。

```
例:   3 1 4 > 4 2 5
      0 7   > 1 8
答え: add1（全要素に1を足す）。見えていない入力でも正しく予測できたら正解
```

- 規則は28種類の基本操作（足し算・掛け算・フィルタ・並べ替え・累積和など）の組み合わせ。深さ3で21,952通り。
- LLM の学習には深さ1〜2だけを使い、組み合わせの約20%は学習から除外した。これにより、次の分割を分けて測れる。
  - ID（学習と同じ分布）
  - Few-shot（例が2個だけ）
  - OOD-組み合わせ（未学習の組み合わせ）
  - OOD-深さ（未学習の3段階の規則）
  - OOD-関連（以前に解いた規則に1手順を足したもの）
- 計算量: LLM の FLOPs、仮説を実際に実行した回数（1問あたり上限2,000回）、実行時間を記録する。

## 3. アーキテクチャ（すべて実装済み、Python / PyTorch、CPU で動作）

| モジュール | 役割 | 脳での対応（比喩） |
|---|---|---|
| 小型 LLM（自作 GPT, 0.1M〜2.7M パラメータ） | 例を見て規則の候補を出す | 言語野・直感 |
| Perception | LLM を使わない安価な特徴量（長さが変わるか等） | 知覚 |
| Router / Executive | 安い処理から順に試し、検証済みの答えが出たら打ち切る | 前頭前野・努力の配分（速い思考／遅い思考） |
| Sparse Experts | 算術・並べ替え・選択などの専門家。必要なものだけ起動 | 機能の局在 |
| Working Memory | いま考えている仮説・反証を容量制限つきで保持 | ワーキングメモリ |
| Long-term Memory | 自分で検証した経験（観察→仮説→実験→結論）を保存・検索 | エピソード記憶（海馬） |
| Hypothesis Generator | LLM サンプル＋部品の組み合わせ探索＋惜しい仮説の修復 | 仮説形成 |
| Novelty Engine | 新規性×もっともらしさ×有用性×検証可能性で評価 | — |
| Simulator / World Model | 仮説を実際に実行して観測と照合（現在は手書きのインタプリタ） | 心の中のシミュレーション |
| Critic | 矛盾・冗長・曖昧さの検出、最も単純な説明を選ぶ | メタ認知 |
| Discovery Loop | 調べる対象を好奇心で選び、情報が最も得られる入力で実験する | 好奇心・能動的な探索 |

## 4. 主な結果

### 4.1 従来手法との比較（LLM 0.8M, 各分割100問）

| 構成 | ID | Few-shot | OOD-組み合わせ | OOD-深さ |
|---|---|---|---|---|
| 小型 LLM 単体 | 14% | 9% | 5% | 3% |
| LLM ＋ 16回サンプル＋多数決（Self-Consistency） | 13% | 10% | 9% | 5% |
| LLM ＋ 16回サンプル＋実行して検証 | 55% | 34% | 23% | 9% |
| LLM を使わない総当たり探索 | 88% | 73% | 84% | 19% |
| **提案モデル** | **89%** | **75%** | **83%** | **40%** |

- 従来の小型 LLM 単体より大幅に良い。
- ただし総当たり探索とは、簡単な分割では互角。勝つのは探索空間が大きい OOD-深さ だけ（40% 対 19%）。実行時間は総当たりの5〜20倍遅い。

### 4.2 どのモジュールが効いたか（フェーズ1: LLM 0.8M、4,500問の対応比較、Holm 補正後）

| モジュール | 外したときの変化（全体） | 判定 |
|---|---|---|
| 実行して検証（Simulator） | 同じ LLM 計算量で正答率が3〜4倍（初期の実験） | 最重要 |
| Router（動的計算） | −14.4 ポイント（OOD-深さ は 56%→20%）。計算量は約2倍 | 有意に効く |
| LLM サンプル | −2.9 ポイント | 有意に効く |
| 組み合わせ探索 | −2.4 ポイント（OOD-深さ を解いた問題の約9割はここから） | 有意に効く |
| 長期記憶 | **+3.3 ポイント（外すと良くなる）** | 有意に悪化させている |
| Experts | **+1.0 ポイント（外すと良くなる）** | わずかに悪化させている |
| Critic | 差なし。ただし「曖昧」判定は信頼度として有効 | 正答率には寄与しない |
| 修復（Repair） | 一度も実行されない | 削除候補 |
| 部品の抽象化（マクロ） | 上積みなし（第2ラウンド） | 既定で OFF |

### 4.3 LLM を大きく・強くすると？（5つの LLM × 3シード）

| LLM | 検証損失（小さいほど強い） | LLM 単体（ID） | 提案モデル（OOD-深さ） | LLM の計算/問 |
|---|---|---|---|---|
| 2.7M・2,000ステップ | 0.88 | 17% | 55% | 764 MFLOPs |
| 0.1M・5,000ステップ | 0.67 | 28% | 59% | 29 MFLOPs |
| 0.8M・5,000ステップ | 0.66 | 33% | 57% | 218 MFLOPs |
| 2.7M・8,000ステップ | 0.46 | 50% | 58% | 698 MFLOPs |
| 0.8M・15,000ステップ | 0.31 | 69% | 58% | 193 MFLOPs |

- 予算が十分（2,000回）なら、LLM 単体の強さが4倍違っても提案モデルの性能はほぼ同じ。性能 / 計算量は最小の 0.1M が最良。
- 予算を絞ると LLM の強さが効いてくる（4.4 参照）。

### 4.4 探索予算を絞ったとき（フェーズ1、各条件4,500問）

全分割の正答率:

| 構成 | 予算 10 | 予算 50 | 予算 200 | 予算 2000 |
|---|---|---|---|---|
| 総当たり探索 | 0.1% | 4.4% | 22.3% | 58.6% |
| 提案 LLM 0.1M | 19.3% | 36.3% | 52.6% | 71.5% |
| 提案 LLM 0.8M（最も強い LLM） | 36.0% | 44.8% | 54.7% | 72.8% |
| 提案 LLM 0.8M − 記憶 | 39.5% | 43.7% | 58.1% | 76.1% |

1. **LLM は予算が少ないほど効く。** 予算10で、LLM の違いは最大 +16.7 ポイント、総当たりとの差は +36 ポイント。予算2000では差が消える。効くのはパラメータ数ではなく LLM 単体の強さ。
2. **長期記憶は予算によって効果の向きが変わる。** 予算10で悪化、予算50でわずかに改善、予算200以上で悪化（強い LLM で約 −3 ポイント）。
3. **正解の出どころが予算で変わる。** 予算2000で OOD-深さ を解いているのは組み合わせ探索（約9割）。予算50では、少ない正解の8割以上を LLM が出している。

### 4.5 失敗と修正から分かったこと

- 初版の長期記憶は OOD-深さ を悪化させた。原因は早すぎる打ち切りではなく、記憶から作った部品に固定の重みを与えていたことによる探索予算の浪費。
  「似た経験だけを検索に使う」設計に変えて改善した。
- 記憶が効く仕組みは「似た経験の結論をそのまま再利用する」ことで、「部品を組み合わせて深い問題を解く」ことではなかった。
- 発見ループの好奇心は、実装の不具合で実験計画がまったく働いていなかった。
- 問題数を300個に増やして再検証した結果:
  - 能動的な実験計画は有意に効く。
  - 好奇心（最も不確かな対象を選ぶ）は、むしろ有意に悪化させる（外すと 84% → 92%）。
  - 以前の24個では差を検出できていなかった。

## 5. 脳に近づいているか（自己評価）

- 機能レベルでは一部似ている: 難しさに応じた努力の配分、仮説と検証、経験の再利用。
- 仕組みは脳と大きく違う:
  - 中身は記号的な探索。
  - 経験で自分の重みが変わらない。
  - 世界モデルは手書きで、学習したものではない。
- 脳らしさを狙った部分（好奇心・抽象化）ほど、効果を示せていない。

## 6. 睡眠と世界モデル

1. **学習した世界モデル（結果あり、1シード・180問なので暫定）**
   - 観察から「操作の結果」を予測するネットワークを学習した。予測は1手順で97.7%、3手順を連続で予測すると89.7%当たる。
   - 候補を頭の中で試してから現実で試すと、**現実で1回しか試せなくても正答率が 33.9% → 67.2%** になった。
     現実だけでこの正答率に届くには、平均77回の実験が必要だった。
   - 頭の中で「合う」とした候補は、99.9%が現実でも合っていた。
   - ただし、頭の中のシミュレーションは LLM の約70倍の計算を使う。現実の実験が高くつく場面でだけ得になる。
2. **睡眠による記憶の定着（実行中）**
   - 昼: 問題を解き、検証済みの経験を記憶に貯める。
   - 夜: 経験の再生・「夢」（同じ規則の新しい例）・古い知識の復習で LLM の重みを更新する。
   - 睡眠なし・復習なし・夢なしと比べる。

## 7. 次の構想: 学習の進み具合を好奇心にする

- 自分で練習問題を作る。分野ごとの伸びを測り、伸びている分野（簡単すぎず難しすぎない）を多めに練習する。夜は睡眠で定着させる。
- 前回の好奇心が効かなかった理由の仮説:
  1. 「不確か」と「学べる」は別物だった。
  2. 調べても自分が変わらなかった。
- 睡眠による定着と組み合わせれば、好奇心が「成長」に結びつく可能性がある。
- 評価: 同じ練習量で「好奇心で練習」「ランダムに練習」「練習なし」を比べる。

## 8. 今後の予定（ユーザーが指示した段階計画）

- フェーズ1（完了）: 診断。探索予算のスイープ・正解の出どころ・アブレーションのやり直し。
- フェーズ2: 基本操作を約100個に増やし、深さ4〜5を含む難しい課題版を追加する。ライブラリ学習と好奇心を再評価する。
- フェーズ3: LLM に答えを丸ごと出させるのではなく、「関わりそうな基本操作」と「次に広げる探索の枝」の確率を出させ、探索の案内役にする。
- フェーズ4: 感情に相当する制御信号（驚き・フラストレーション・自信）を1つずつ ON/OFF で検証する。

## 9. Claude に相談したいこと

1. 「人間の脳とほぼ同じモデル」を目標にするとき、この方向性（小型 LLM ＋認知モジュール、実験で1つずつ検証）は妥当か。もっと本質的に取り組むべき脳の性質は何か。
2. LLM は「予算が少ないときの近道」として効き、予算が十分だと探索が主役になった。この役割分担をどう解釈し、フェーズ3（LLM を探索の案内役にする）をどう設計すべきか。
3. 長期記憶は予算によって効果の向きが変わり、全体では悪化させた。脳のエピソード記憶に近く、かつ役に立つ設計はどうあるべきか。
4. 「最も不確かな対象を選ぶ」好奇心は有意に悪化させた。学習の進み具合を好奇心にする案は妥当か。
5. 学習した世界モデルは現実の実験を大幅に減らしたが、計算は重い。スマホで使うにはどう軽くすべきか。
6. リスト変換という1つの課題だけで結論を出している。次に試すべき課題は何か。
