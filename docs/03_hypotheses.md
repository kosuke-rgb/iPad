# Step 3 — 実験仮説

各仮説には「どうなったら棄却するか」を先に決めておく。

| ID | 仮説 | 検証方法 | 棄却条件 |
|---|---|---|---|
| H1 | 検証器（Simulator）付きのサンプリングは、同じ LLM の多数決（Self-Consistency）より未知問題に強い | S と E の OOD 正答率を比べる（LLM FLOPs はほぼ同じ） | S ≤ E |
| H2 | 提案モデルは、同じ LLM の Baseline A〜E より OOD 正答率が高い | OOD-組み合わせ / OOD-深さ の正答率と95%信頼区間 | 信頼区間が重なり、差がない |
| H3 | 提案モデルは、LLM なしの総当たり探索より少ない Simulator 回数で同等以上の正答率を出す | 正答率と平均 Simulator 回数 | 同じ予算で総当たりに負ける |
| H4 | Router（動的計算）は、精度をほぼ落とさずに計算量を減らす | 提案 vs 提案−Router | 計算量が減らない、または正答率が2ポイント以上落ちる |
| H5 | 長期記憶（経験＋マクロ）は、特に OOD-深さ で効く（深さ2の経験を深さ3で再利用できる） | 提案 vs 提案−Memory | OOD-深さ の正答率が改善しない |
| H6 | 各モジュール（Experts, Compose, Repair, Critic, LLM サンプル）はそれぞれ正の寄与を持つ | アブレーション | 外しても正答率・計算量が悪化しない → **削除候補** |
| H7 | 発見ループで、情報利得による実験計画はランダムな実験より少ない問い合わせで規則を特定できる | discovery_eval: Full vs −Active | 特定数が増えない |
| H8 | 好奇心による対象選択は、ランダムな選択より多くの規則を特定できる | Full vs −Curiosity | 特定数が増えない |
| H9 | int8 量子化で精度はほぼ変わらず、モデルサイズは小さくなる | mobile/quantize.py | 正答率が2ポイント以上落ちる |

## 注意（結果の解釈）

- DSL の世界の法則はインタプリタとして既知である。学習した世界モデルではないので、
  Simulator の効果は「完全な世界モデルがある場合の上限」と解釈する。
- 評価は1つの領域（リスト変換）だけで行う。言語や科学の問題へ一般化できるかは、別に検証が必要。
