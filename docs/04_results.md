## 4. 仮説の判定

| ID | 仮説 | 判定 | 根拠 |
|---|---|---|---|
| H1 | 検証付きサンプリング > Self-Consistency | **支持** | S と E は LLM FLOPs が同じ（229M）だが、ID 55% 対 13%、OOD-組み合わせ 23% 対 9%。多数決は「多数派の誤り」を選ぶだけだった |
| H2 | 提案モデル > Baseline A〜E | **支持** | 全分割で信頼区間が重ならない（例: OOD-深さ 40% 対 最大 9%） |
| H3 | 提案モデルは総当たりより少ない Simulator 回数で同等以上 | **一部支持** | ID / Few-shot / OOD-組み合わせ は同等（差は信頼区間内）。OOD-深さ は 40% 対 19% で有意に上回る。Simulator 回数は 473 対 636 で少ない。**ただし実時間は約12倍遅い**（97ms 対 8ms）。LLM の計算がこの規模では割に合っていない |
| H4 | Router は精度をほぼ落とさずに計算量を減らす | **支持（精度はむしろ向上）** | Router なしでは Simulator 回数が4.2倍、実時間が2.5倍。OOD-深さ は 40%→23% に低下（全段階を実行するうちに予算を使い切る）。ID などは +1〜2 ポイントで誤差の範囲 |
| H5 | 長期記憶は OOD-深さ で効く | **棄却** | 記憶なしのほうが OOD-深さ 48% 対 40%（信頼区間は重なるが、向きが逆）。Few-shot だけ +4 ポイント |
| H6 | 各モジュールは正の寄与を持つ | **モジュールごとに判定**（下表） | |
| H7 | 情報利得による実験計画 > ランダムな実験 | **支持されず** | Full 67% 対 −Active 61%。しかし入力も対象もランダムな Passive も 67% |

| H9 | int8 量子化で精度はほぼ変わらない | **ほぼ支持** | サイズ 71% 減、速度 1.36 倍。ID と OOD-組み合わせ は ±2 ポイント。OOD-深さ は 29%→25%（誤差の範囲だが要確認） |

### モジュールごとの判定（Step 13: 効果が確認された機能だけ残す）

| モジュール | 外したときの変化 | 判定 |
|---|---|---|
| Simulator（検証） | S 対 E で、同じ LLM 計算量のまま正答率 3〜4 倍 | **残す（最重要）** |
| LLM サンプル | ID −10、Few-shot −14 ポイント | **残す** |
| 組み合わせ探索（Compose） | Few-shot −8、OOD-組み合わせ −5、OOD-深さ −4 ポイント | **残す** |
| Router（動的計算） | 計算量が数倍になり、OOD-深さ −17 ポイント | **残す** |
| Sparse Experts | 正答率はほぼ変わらない。実時間は 20% 短縮 | 残す（効果は計算量のみ） |
| Critic | 正答率は変わらない。ただし「曖昧」判定は信頼度として有効（曖昧: 正答率 43%、それ以外: 85%） | 残す（出力の信頼度として） |

| 長期記憶 | OOD-深さ −8 ポイント（悪化） | **設計を見直す** |

## 5. 分かったこと

1. **効いているのは「生成 → 実行して検証」のループ**。同じ LLM でも、検証なしの多数決（E）と検証あり（S）で結果が大きく違う。調査で予想したとおり（docs/01_research.md の結論1）。
2. **この規模では、LLM そのものは弱い**。LLM 単体（A）の正答率は 3〜14%。「総当たり探索の順序を良くする」役割でしか効いていない。提案モデルが総当たりに勝つのは、探索空間が予算より大きい OOD-深さ だけ。
3. **動的計算（Router）は精度も計算量も改善した**。「難しい問題にだけ計算を使う」は、この実験では正しかった。
4. **「脳っぽい」モジュールの多くは、まだ効果を示せていない**（長期記憶・好奇心・能動的な実験計画・修復）。原則（19章）に従い、「ある」ことを成功とはみなさない。

## 6. 修正履歴（実験で見つかった不具合）

第1回の結果は `results/main_v1_before_fix.json` に残してある。

- **組み合わせ探索の長さのペナルティ**: 部品単位で数えていたため、記憶のマクロ（2手順）を使った長さ4の候補が不当に安く見え、予算を浪費していた。プリミティブ単位に変更したところ、提案モデルの OOD-深さ が 29%→40% になった。
- **発見ループの好奇心**: 仮説が1つもない対象の不確実性を ∞ にしていたため、問い合わせがすべてそこに吸い込まれ、実験計画が一度も働いていなかった（設計時の仮説数が常に0）。有限値に変更し、仮説が1つに絞れた対象には確認の実験を割り当てた。発見ループ全体では 51%→67%。

## 7. 次のステップ

1. **長期記憶の再設計**: 記憶の候補を「検証済み」だけでなく、別の入力でも正しかったものに限る。マクロは、使って成功した回数で重みづけする。
2. **発見ループの再設計**: 問い合わせの総数（96回）に対して、仮説を作る側がボトルネックになっている（仮説0個の対象が多い）。実験計画よりも、仮説の生成力を上げるほうが先。
3. **Repair の位置**: Compose の上限を予算の一部に抑え、Repair に予算を残す実験をする。
4. **LLM を強くする**: 学習ステップ・モデルサイズを増やし、「LLM が強くなるほど、認知モジュールの寄与はどう変わるか」を測る（15章の Performance / Compute の本題）。
5. **複数シード**: 主要な比較を3シード以上で繰り返し、信頼区間を狭める。
6. **別の領域**: 言語・算数の問題で同じアブレーションを行い、結論が一般化するかを確かめる。
